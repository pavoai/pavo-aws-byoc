# Data handled

"Cell key" means the customer-managed KMS key you pass as `cell_kms_key_arn`.

## Data stores (stage 2)

| Store | Holds | Encryption at rest | In transit |
|---|---|---|---|
| RDS PostgreSQL | Application data | Cell key | TLS forced by the default PostgreSQL 16 parameter group (`rds.force_ssl = 1`); password auth. Ingress is the EKS cluster SG |
| RDS PostgreSQL for Temporal (`temporal_mode = "self_hosted"`) | Workflow state | Cell key | TLS (regional RDS root CA shipped to the pods) |
| ElastiCache Redis (3 groups) | Caches and queues | Cell key on **new** groups; existing groups keep their previous key (`ignore_changes`) | `redis_security_phase` (default `off`). A strict instance must be created with `enforced` (TLS + AUTH; the plan fails otherwise); on standard posture Pavo passes `enforced` at create |
| EFS | Shared files for the workloads | Cell key on **new** filesystems; existing filesystems keep their previous key (`ignore_changes`) | File-system policy denies non-TLS and mounts without an access point. IAM-signed mounts: `efs_iam_auth_enforced` (default `false`). Ingress is the EKS cluster SG |
| S3 `onboarding` and `data` buckets | Uploaded and processed files | Cell key for **new objects**; existing objects stay SSE-S3 until rewritten | HTTPS |
| S3 Elasticsearch snapshots (`es_mode = "self_hosted"`) | Search index snapshots | Cell key | HTTPS |
| S3 identity state (`zitadel_mode = "self_hosted"`) | Terraform state for the identity Job | Cell key | HTTPS |
| SQS queues (worker + connector_sync) | Work items, which may reference customer data | Cell key | HTTPS |
| SNS topics (`data_fetcher`, `dedup`, `connector_sync`) | Fan-out to the queues | Cell key on **new** topics; existing topics keep their previous key (`ignore_changes`) | HTTPS |
| EBS volumes on the `gp3-cmk` storage class (stage 1, with `enable_observability`) | The in-VPC observability stack | Cell key | — |
| Node EBS default / keyless gp3 (stage 1) | Worker nodes and volumes created without an explicit key | Cell key (account+region default). Existing volumes keep their key until replaced | — |
| Stage 1 Terraform state bucket | Terraform state | Cell key when `create-state-backend.sh` is passed the CMK | HTTPS |

Buckets block public access, and versioning is on for the application and
identity-state buckets (`terraform-omnistrate-aws/main.tf`,
`zitadel_provision.tf`).

## Secrets

| Secret | Source | Stored in | Notes |
|---|---|---|---|
| RDS master password | Generated by RDS (`manage_master_user_password`) | AWS Secrets Manager, encrypted with the cell key | Synced by a **namespaced** SecretStore `pavo-aws-sm` and per-instance ESO role `pavo-eso-<instance_id>`. The cell ESO role does not read instance secrets unless `legacy_eso_cell_secret_read = true` |
| Application secrets (API keys, OAuth client secrets) | Pavo, through Omnistrate secrets | Kubernetes Secrets in the instance namespace | Listed as Pavo-managed secrets in [inputs-contract.md](inputs-contract.md) |
| Identity OIDC client secret | Stage 3 | Passed to stage 2 as an input and out again as a sensitive output for the application's configuration | With self-hosted identity, the in-cluster Job produces it instead |
| Your IdP client secret (self-hosted identity) | You, as the Omnistrate instance parameter `primary_external_identity_provider_client_secret` (type Password) | Omnistrate's parameter store, the stage 2 Terraform state (the `zitadel-idp-client-secret` Secret resource), and a Kubernetes Secret in the instance namespace | Used only by the in-cluster identity Job |
| Temporal payload codec key (optional) | Instance parameter `temporal_payload_codec_key` | Kubernetes Secret, Terraform state, and a stage 2 output that Omnistrate reads to render the charts | Encrypts workflow payloads |
| Generated tokens (worker API secret, capability tokens, VAPID key) | Terraform `random_password` / `tls_private_key` | Kubernetes Secrets, Terraform state, and stage 2 outputs that Omnistrate reads to render the charts | |
| Grafana admin and database passwords (`enable_observability`) | Terraform `random_password` in stage 1 | Kubernetes Secrets, and your stage 1 state | |

Terraform state contains the generated secrets above. Stage 1 state is in your
S3 backend; stage 2 state is managed by Omnistrate and stored as Kubernetes
Secrets in the cell's `omnistrate-terraform` namespace (see architecture.md).

**Not under the cell key.** Kubernetes Secrets, including the stage 2 state
Omnistrate keeps as Secrets, are encrypted as the cluster's Secrets are: the
cell cluster is Omnistrate-created and sets no KMS envelope key on the EKS
control plane (architecture.md). Existing Redis groups, EFS file systems, SNS
topics and S3 objects keep their previous key, as the table above notes.

## What leaves your account

Every external service the application or the modules can reach, from the
instance parameters, the Pavo-managed secrets and the strict Helm profile in
`spec/spec-byoc.yaml`. "Forced off" means the `aws-strict-profile` Helm layer
blanks the setting on every render, whatever the stored instance parameter
says; "not applicable" means strict requires the self-hosted mode at creation.
On strict, a service that is neither in-VPC nor behind an AWS endpoint is
reachable from the instance namespace only through a destination listed in the
cell's `strict_egress_extra_destinations` (for example your outbound proxy),
because the egress policy allows nothing else.

| Service | What for | Default | On strict |
|---|---|---|---|
| Omnistrate (control plane) | Applies the modules and reads every stage 2 output to render the application charts, sensitive outputs included (architecture.md) | always | unchanged |
| Amazon Bedrock, US cross-region inference profiles (`us.*`) | LLM calls and embeddings | on (`llm_cloud_only = true`) | available over the Bedrock interface endpoints; the profile forces Bedrock-only LLM and Titan embeddings |
| OpenAI (`openai_api_key`) | Alternative LLM and embedding provider | empty | forced off: key blanked for the worker, onboarding and knowledge services |
| Anthropic API (`anthropic_api_key`) | Kept for compatibility; Claude runs through Bedrock | empty | unused |
| Elastic Cloud (`es_mode = "cloud"`, `elastic_api_key`) | Search index | `cloud` | not applicable (`self_hosted` required) |
| Grafana Cloud (`grafana_mode = "cloud"`) | Metrics and dashboards | `cloud` | not applicable (`self_hosted` required) |
| Temporal Cloud (`temporal_mode = "cloud"`) | Workflow engine, payloads encrypted with the codec key when set | `cloud` | not applicable (`self_hosted` required) |
| Pavo identity service `auth.pavoai.com` (`zitadel_mode = "cloud"`) | Sign-in | `cloud` | not applicable (`self_hosted` required; Zitadel runs in the instance namespace) |
| Your identity provider (`primary_external_identity_provider_*`, self-hosted identity) | Federated sign-in | off | configured independently of the posture; the in-cluster Zitadel reaches it only through `strict_egress_extra_destinations` or an in-VPC address |
| GitHub and Bitbucket (`bitbucket_oauth_*`, connector tokens) | Repository connectors | available | configured independently of the posture; reachable only through `strict_egress_extra_destinations` |
| HubSpot (`hubspot_enabled`, `hubspot_*`) | Contact sync on sign-up and login | off | forced off |
| Langfuse (`langfuse_enabled`, `langfuse_*`) | LLM tracing, exports prompts and completions | off | forced off |
| Brevo (`brevo_api_key`) | Transactional email on GCP | empty | key blanked; on AWS email uses SES (below) |
| Amazon SES (`email_enabled`) | Login and notification email | empty (derived) | independent of the posture; over the `email` interface endpoint |
| Slack (`enable_slack_notifications`, `slack_oauth_*`) | Task notifications | off | forced off |
| E2B (`e2b_api_key`, templates) and Modal (`modal_token_*`, Pavo-managed) | Sandbox-backed agent computer sessions | empty / set by Pavo | forced off: keys and templates blanked, computer backend `pavo_custom` |
| AWS Lambda MicroVMs (`aws_microvm_*`) | Alternative sandbox backend in your account | off | image, region and worker secret blanked; managed image publishing requires `standard` (`microvm_image.tf`) |
| Google Cloud Storage via gcsfuse (`sandbox_gcsfuse_*`) | Data bucket mount for sandboxes | off | forced off |
| Amplitude, Sumble, Parallel (`*_api_key`) | Product analytics, company enrichment, web search | empty | keys blanked |
| Google Gemini (`gemini_api_key`, Pavo-managed) | AI-driven browser actions | set by Pavo | key blanked |
| Pavo alert endpoint (`pavo_app_alerts_enabled`, stage 1) | Sanitised alert metadata | off | runs in the stage 1 observability namespace, outside the instance policy; its own policy leg opens `pavo_webhook_cidr` when enforcement is on |
| Your alert webhook (`customer_alert_webhook_url`, stage 1) | Alerts to your channel | empty | same namespace; its leg opens `customer_alert_cidr` |
| Let's Encrypt | Public ingress certificates | standard only | not used; the ACM certificate comes over the `acm` interface endpoint |
| Sigstore and `ghcr.io` | Image-signature verification by the policy controller (`cosign-system`) | standard posture | no internet route on a private cell; pulls of the ECR copies are not signature-checked today (network-and-egress.md) |
| Pavo's artifact-plane ECR, S3 provider mirror and chart bucket | Images, Terraform providers, the Temporal chart | always | over the ECR interface endpoints and the S3 gateway endpoint |
| Public Helm chart repositories | Stage 1 add-on charts | stage 1 apply | from the machine running stage 1, not from the cell |

Bedrock calls enter through the PrivateLink endpoint in your region (with VPC endpoints enabled, the default). Claude models are invoked through AWS's US cross-region inference profiles (us.*), so a request may be processed in us-east-1, us-east-2 or us-west-2; it stays within US AWS regions.
